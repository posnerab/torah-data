# Hebcal API helpers

These dependency-free Python helpers exercise the Hebcal calendar, leyning,
and zmanim APIs and write deterministic UTF-8 JSON. They are intended for
manual generation and verification of mostly static source snapshots, not a
scheduled refresh service.

Hebcal does not require API keys. Its public API is rate-limited, so the client
uses range requests, caps leyning and zmanim chunks at 180 inclusive days, and
backs off on HTTP 429 and transient server failures.

## Examples

Run from the repository root with the workspace Python:

```powershell
G:\Projects\.venv\Scripts\python.exe scripts\hebcal\hebcal_api.py `
  calendar --year 2026 --output G:\Projects\tmp\hebcal\calendar-2026.json

G:\Projects\.venv\Scripts\python.exe scripts\hebcal\hebcal_api.py `
  leyning --start 2026-01-01 --end 2026-12-31 `
  --output G:\Projects\tmp\hebcal\leyning-2026.json

G:\Projects\.venv\Scripts\python.exe scripts\hebcal\hebcal_api.py `
  zmanim --start 2026-01-01 --end 2026-12-31 --zip 53216 `
  --output G:\Projects\tmp\hebcal\zmanim-53216-2026.json

G:\Projects\.venv\Scripts\python.exe scripts\hebcal\hebcal_api.py `
  request --endpoint /converter --param cfg=json --param g2h=1 `
  --param gy=2026 --param gm=7 --param gd=26 `
  --output G:\Projects\tmp\hebcal\converter-2026-07-26.json
```

Omit `--output` to print JSON to standard output. For location-aware calls,
choose exactly one of `--zip`, `--geonameid`, or the
`--latitude`/`--longitude` pair.

The typed commands normalize the APIs currently used by the semantic model.
The `request` command can exercise any other JSON GET endpoint documented in
Hebcal's OpenAPI catalog without adding another one-off script.

## Tests

```powershell
G:\Projects\.venv\Scripts\python.exe -m unittest discover `
  -s scripts\hebcal -p "test_*.py"
```

The unit tests use fake responses and do not call the network. A focused live
smoke check can use a one-day range for each command.

## Immutable corpus

See [STORAGE.md](STORAGE.md) for the repository's data-materialization
strategy and [corpus-v1.json](corpus-v1.json) for the exact scope. The
location-independent corpus covers Hebrew years 1 through 6000 and is generated
once into immutable, checksummed Parquet partitions. Later transformations and
semantic-model relationships may change, but completed core partitions may
not be regenerated or overwritten.

The REST helper is for focused verification. Full population uses pinned local
Hebcal packages so it does not depend on thousands of web requests.
`proleptic_hebcal.mjs` supplies two version-pinned compatibility corrections
for negative absolute dates: normalized `dayOnOrBefore` arithmetic and
Shabbat-aware leyning lookup. Tests require exact parity with upstream leyning
through a modern positive year and cover BCE boundary cases separately.

Install the pinned one-time population dependencies:

```powershell
Set-Location G:\Projects\torah-data\scripts\hebcal
npm install
G:\Projects\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Build a disposable pilot:

```powershell
G:\Projects\.venv\Scripts\python.exe build_corpus.py `
  --start-year 1 --end-year 100 `
  --output-root G:\Projects\tmp\hebcal-corpus-v1
```

After the source and pilots are frozen, populate and permanently finalize all
60 partitions:

```powershell
G:\Projects\.venv\Scripts\python.exe populate_corpus.py `
  --output-root G:\Projects\torah-data\data\hebcal\corpus-v1 `
  --workers 3
```

There is deliberately no overwrite or force option. See
[MIGRATION.md](MIGRATION.md) and
[schemas/corpus-v1.md](schemas/corpus-v1.md).
